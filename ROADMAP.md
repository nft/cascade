# Roadmap

What comes after 0.1.0, roughly in order. It is a plan, not a schedule; [CHANGELOG.md](CHANGELOG.md) records what has shipped.

## Next

1. **OpenAPI import**, so the operation palette comes from your own spec instead of the demo catalog.
2. **Value generators** for fields: ids, emails, random strings and numbers, picks from a list, and sequences.
3. **Parallel branches**, so independent nodes run at the same time, with concurrency limits and per-environment rate limits.
4. **Pause and resume** for long runs, next to Stop.

## Later

- A run summary with the records created per node, the failures and the duration.
- Per-node log detail (off, status only, or the full request and response) and a cap on stored logs, so large loops keep the logs panel usable.
- Default headers per environment.
- Field values generated by a language model you bring, through OpenRouter or a local Ollama, and checked against the field's schema.

## Not scheduled

Ideas that need real demand before they move up:

- A headless runner that executes a board file from the command line, for CI.
- A public collection of ready-made boards for common test targets.
- A server build of the same engine for teams.
- Conditional nodes, OAuth flows that refresh their own tokens, and sources other than HTTP.
